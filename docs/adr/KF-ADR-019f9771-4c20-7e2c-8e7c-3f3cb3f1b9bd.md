# KF-ADR-019f9771-4c20-7e2c-8e7c-3f3cb3f1b9bd: Kungfu owns native Work Control vocabulary

## Context

Atlas uses Mission and Go as control-plane workflow language. Reusing those
terms as Kungfu's default product vocabulary made the GUI group unrelated work
under an Atlas Mission and obscured which system owned a write. Kungfu already
has immutable Initiative and Assignment fact surfaces and a federated work
projection, but its Profile identity and default presentation still exposed
the older Atlas-shaped names.

## Decision

### 1. The active Kungfu Profile is Work Control

New installations discover `kungfu.work-control` version `4.0.0`. Native
public and write surfaces use Work Control, Initiative, Assignment, Project
Cut, and Portfolio. Atlas may provide source metadata to admission, but an
Atlas Mission identifier is never an implicit Initiative identifier.

Admission must receive an exact Initiative `WorkRef` or a content-addressed
Initiative admission envelope. The envelope binds the Initiative id, title,
intent, source authority, source object id, and immutable source version root;
an id alone is insufficient. An Assignment retains the complete source work
definition for audit, while its native parent is the explicitly promoted
Initiative card.

### 2. Portfolio is a read model, not a global controller

Portfolio federates exact `WorkRef` observations across owning workspaces. It
may report availability, conflict, and portfolio state. It has no write
authority, atomic global cut, or completion authority. Each workspace remains
the sole authority for its local work objects.

### 3. Atlas vocabulary is an explicit compatibility boundary

The `kungfu.mission-control` contract worlds, surfaces, payloads, roots, and
readers remain exact and read-only. The `kungfu atlas` bridge and hidden
compatibility commands may expose Atlas terminology because their boundary is
explicit. Default Kungfu GUI, TUI, CLI help, Agent catalog, and native machine
receipts must not expose Mission or Go vocabulary.

No fact rewrite or historical root migration is permitted. Rollback restores
the prior Atlas writer only through the declared authority receipt; it does not
rename or delete native evidence.

### 4. Project Cut remains the settlement boundary

Work Control changes naming and admission identity, not completion authority.
An Assignment can advance only through its declared lifecycle gates. Completion
review and continuation decisions remain evidence-bound, and Project Cut
remains the highest ordinary settlement interface.

Nonterminal continuation decisions (`reopen` and `request-evidence`) begin a
new completion cycle. They must return the Assignment to `stage-ready` so a
new completion claim and independent review can be appended. Historical
claims, reviews, and decisions remain immutable evidence; only terminal
continuation decisions may make the Assignment eligible for sealing.

### 5. Settled outcomes inform design without becoming Work authority

A rooted outcome may be published only as an additive binding to an exact
settled Assignment state and query proof. Portfolio federation deduplicates
replica observations by settled state root and reports partial, sealed-only,
unqualified, and conflicting coverage without guessing missing legacy facts.

Open-card selection and Work Design advice may use only exact, as-of-compatible
outcomes. Estimates retain attributable active engineering time, excluded
waits, rework, coverage, cohort, and evidence roots. They remain advisory:
sample thresholds may qualify a future policy candidate, but never authorize a
work definition or create another Work writer. Any unavailable, stale, or
root-mismatched history path falls back visibly to human-authored capture.

## Falsification and qualification

This decision is false if:

- admission derives an Initiative from Atlas Mission metadata;
- a default Kungfu human or machine surface emits Mission or Go terminology;
- Portfolio claims write, atomic-cut, or completion authority;
- a successor write appends to a legacy fact surface;
- legacy evidence changes any sealed coordinate or payload byte; or
- a completion path bypasses Assignment lifecycle or Project Cut evidence.

Qualification requires source Profile validation, explicit-parent admission
tests, native CLI and TUI surface tests, a vocabulary gate, legacy compatibility
fixtures, workspace federation tests, nonterminal completion-cycle regression
tests, and source acceptance. Installed Work Design preflight qualification also
requires exact runtime closure in the wheel and assembled product, a neutral
read-only CLI surface, fail-closed runtime absence, and an installed-product
smoke that verifies the request and response schemas without mutation.

## Consequences

- Atlas and Kungfu can evolve their control languages independently.
- Initiative becomes an intentional parent card instead of an inherited label.
- Assignment is the only native dispatch unit.
- Portfolio provides a coherent cross-workspace view without creating a second
  authority.
- Settled outcome history can improve decomposition and budgets while final
  work definitions remain human-authorized.
- Legacy readers remain auditable and bounded instead of leaking into the
  default product.
