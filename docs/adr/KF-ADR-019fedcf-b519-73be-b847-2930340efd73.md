# KF-ADR-019fedcf-b519-73be-b847-2930340efd73: Temporal release admission

- Status: accepted; implemented and qualified by PR #2912
- Date: 2026-08-10
- Category: release admission / temporal proof path
- Related: [KF-ADR-019fe996-1912-7144-8fa5-3fceaa416365](KF-ADR-019fe996-1912-7144-8fa5-3fceaa416365.md)

## Post-cutover note (2026-08-15)

This ADR preserves the now-retired dual-read transition as historical context.
The live contract has since cut normal release admission over to its sole
`fact-only` mode: exact Buildchain Fact roots and KFR2 path receipts are the
compatibility authority, digest projections are non-authoritative, and the
environment-selected `legacy-exact` path no longer exists. The retained
exact-digest behavior is isolated behind the independently sealed offline
rollback contract and is never eligible for normal admission. Read the
dual-read sections below as the migration phase that preceded that cutover.

## Context

Kungfu's publication consumer accepted a bounded list of Buildchain contract
digests. That list was exact, but it did not prove why a historical runtime
contract remained compatible with the current verifier. Separately, release
candidate and promotion workflows now emit immutable provenance objects, but
release admission did not consume their source tree, candidate ancestry,
qualification, contract, and authority relations.

Treating either the legacy digest list or Git ancestry as sufficient authority
would recreate an implicit compatibility graph. The admission boundary instead
needs one explicit, bounded path joining Buildchain's protected compatibility
proofs to the exact Kungfu release-provenance object and publication evidence.
It must retain a reversible dual-read window without rewriting historical facts
or performing a real publication during qualification.

## Decision

Release admission verifies a closed `kungfu.temporal-release-admission-contract/v1`.
For the current contract, the caller supplies a direct one-edge path. A listed
historical Alpha contract is accepted only by the three explicitly named
Buildchain proofs for the advanced promotion workflow, promotion action, and
release-candidate workflow. The verifier never searches, infers a major-line
relation, reverses an edge, or accepts an unlisted proof.

The path also binds the exact repository, source commit and tree, promotion
commit, release-provenance object, artifacts, Buildchain runtime and contract,
qualification, consumer approval, and release authority. Kungfu independently
verifies the provenance object and the protected Buildchain proof bytes before
asking the KFR2 temporal verifier to evaluate the ordered path at a rooted Cut.
Both accepted and rejected requests return deterministic, payload-free rooted
receipts and stable diagnostic roots.

During dual-read, `publicationContractDigests` and the proof-path keys must be
the same exact set. Mismatch is rejection. The bounded rollback switch
`KUNGFU_TEMPORAL_RELEASE_ADMISSION_MODE=legacy-exact` restores only the prior
exact-list decision and still emits a rooted direct-path receipt; it does not
mutate the provenance object, compatibility proofs, Cut, or any historical
record.

## Consequences

The release consumer can now explain every historical-contract decision with a
bounded proof path rather than a digest exception. Orphan roots, malformed Git
SHAs, stale target surfaces, provenance drift, ancestry failure, policy/proof
parity drift, and path overreach fail closed with deterministic evidence.

The migration temporarily carries two policy projections and a Python bridge
from the Node release consumer into the independent KFR2 verifier. That cost is
intentional and bounded. A later cutover may remove the legacy list only after
all live release callers provide provenance inputs and the rollback campaign is
qualified; this decision does not authorize that removal or a real Alpha
publication.
