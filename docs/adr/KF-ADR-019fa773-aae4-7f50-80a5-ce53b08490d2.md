# KF-ADR-019fa773-aae4-7f50-80a5-ce53b08490d2: First-party longitudinal evolution map

- Status: accepted
- Date: 2026-07-28

## Context

Kungfu's current source spans native storage, multi-language bindings, agent
runtime, KFX and Profile composition, Project Cut and Xinfa, Work Control,
Primitive governance, product surfaces, qualification, and release evidence.
Opening the repository at one point in time therefore imposes a much larger
mental model than the sequence in which those abstractions became necessary.

The v4 history contains repeated compression passes: a local capability is
proved, its semantics are separated from its provisional placement, and the
stable part moves into a lower shared authority. Later delivery then relies on
the earlier compression. Git and pull requests preserve evidence for this
history, but an unbounded chronological log is not an onboarding model.

Current architecture documents must remain authoritative. A historical map
that copies their current claims would create a second truth surface and drift.
Conversely, a single narrative article would grow without bound and invite
silent rewrites of settled interpretation.

## Decision

Kungfu owns a versioned longitudinal Evolution Map organized as Era, Stage, and
Evidence records. An Era names a sustained abstraction thesis. A Stage exists
only for a load-bearing capability compression or authority transition, not
for each feature. Evidence is exact public PR, commit, ADR, or current document
material retained by the Stage.

Era and Stage Markdown records carry one typed JSON fence. Once a record exists
on the protected base its meaning is append-only: later correction or
replacement adds an `amends` or `supersedes` Stage. The validator rejects
identity collisions, forward or dangling dependencies, discontinuous authority
transitions, invalid evidence, missing current references, and mutation or
deletion of settled records.

A deterministic generator folds the records into three human views and one
machine view: evolution timeline, current-authority navigation, role-oriented
reader routes, and `map.json`. These outputs are disposable projections. The
current contracts referenced by a Stage remain authoritative for their domain;
Xinfa remains the sole semantic graph, impact, selection, stale-state, and
bounded context authority.

Documentation entrypoints and a paired Xinfa route expose the map before broad
repository traversal. Pull requests declare one evolution impact from `none`,
`extends`, `opens`, `settles`, or `supersedes`. The documentation and source
gates regenerate-check the projections and settled-history boundary.

## Consequences

- New readers can learn the causal abstraction spine before traversing the
  current cross-section, then cross into exact present authority.
- Historical interpretation becomes reviewable and extensible without
  rewriting earlier evidence.
- The record burden is intentionally high enough to prevent one Stage per
  feature: a Stage must show pressure, compression, authority transition,
  downstream leverage, and exact evidence.
- The map can lag or misinterpret history. Such errors remain visible through
  amendments, independent review, and exact evidence; the map never overrides
  current contracts or runtime facts.
- A future implementation that introduces another graph, database, selector,
  daemon, or current-authority corpus for this purpose violates this decision.
- The design is falsified if ordinary changes require Stage churn, generated
  views cannot be rebuilt deterministically, or readers must still reconstruct
  the same history from unbounded PR search.
