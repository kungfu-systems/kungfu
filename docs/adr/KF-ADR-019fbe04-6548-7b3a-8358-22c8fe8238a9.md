# KF-ADR-019fbe04-6548-7b3a-8358-22c8fe8238a9: Exit history surfaces are observers over unchanged domain authority

- Status: accepted
- Date: 2026-08-01

## Context

Kungfu's durable data owners already expose exact roots, portable members,
bounded verification, and projection rebuild paths. Users and adjacent agents
still lacked one public route to observe whether those protections were merely
installed, evaluated for a selected scope, fully verified, or explicitly
degraded. A GUI or TUI implementation that inferred this from SQLite, caches,
paths, or UI state would create a second semantic authority and could silently
overstate recoverability.

The public surface must also distinguish software portability from off-host or
physical-media durability. A successful export can prove only the declared
package closure and member roots; it cannot prove that another independent
copy exists.

## Decision

Add the `kungfu exit history` command family as a public projection over the
existing Exit Bundle builder, verifier, importer, and member-domain rebuild
services. `status` is read-only. With no request it reports only contract and
eligible-adapter availability. With a request it constructs a thin inventory
projection and therefore cannot claim content availability. `export` requires
an explicit output file, verifies the package, and records only a disposable
observer receipt containing roots, loss, and member verification results.
`verify` remains registry-free and read-only. `import` and `rebuild` preserve
validation-by-default and require explicit execute authorization.

The observer receipt is not history authority. It contains no package path,
may be deleted without semantic loss, and changes a general status only to
`verified` or `degraded` according to the last verified package's explicit
loss. GUI and TUI invoke the same Core `status --json` command, display that
state, coverage, last export identity, and the exact Core recovery action. They
never settle Work, reinterpret member roots, or rebuild from presentation
state.

Only Episode and Fact projections with existing owner services are exposed by
the initial rebuild command. Unknown projection names fail closed. Adding a
new rebuild target requires a domain-owned service and a new qualified
contract change.

## Consequences

Benefits:

- users and agents receive one machine-readable protection vocabulary across
  CLI, GUI, and TUI;
- explicit thin loss and full verification remain visible rather than being
  compressed into a generic success state;
- exported package bytes never flow through stdout, and observer state never
  captures private source or destination paths;
- projection recovery reuses domain authorities instead of copying caches.

Costs and limits:

- the last-export observer is local and disposable, so deleting it returns the
  UI to honest `contract-ready` rather than proving that no export exists;
- the public surface does not schedule backups, choose storage media, or prove
  an off-host copy;
- stable-release and non-Darwin packaged-product behavior need separate
  qualification before wider release claims.

The decision is falsified if GUI/TUI derive protection truth independently,
status mutates a member authority, a thin package appears fully protected,
export leaks package bytes or paths through machine output, rebuild copies a
cache as truth, or any write proceeds without the existing explicit execute
and authorization boundaries.
