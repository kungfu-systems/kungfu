# KF-ADR-019f878c-5480-7890-bc64-9b2aab7e9aa5: Assignment request capture is build-free, content-addressed, and pre-admission

- Status: accepted; implementation and qualification staged
- Date: 2026-07-22
- Category: Work Control / Assignment ingress / workspace capture
- Related: [KF-ADR-019f86da-4f90-7d61-8afa-33d66ca05d36](KF-ADR-019f86da-4f90-7d61-8afa-33d66ca05d36.md),
  [KF-ADR-019f86da-4f90-713d-8626-d70bca82cb76](KF-ADR-019f86da-4f90-713d-8626-d70bca82cb76.md), and
  [Initiative and Assignment L3 contract](KF-ADR-019f8759-ab29-7627-bc04-6aba547ea45f.md)

## Context

An agent or external control plane must be able to hand work to Kungfu before a
compiled Core, installed product, selected Initiative, or live journal exists.
Treating that handoff as Assignment admission would invent authority and make a
toolchain build a prerequisite for capture. Treating Home as a global write
fallback would contradict the workspace contract.

Atlas goal cards also carry more work-definition fields than the successor L3
record currently interprets. Capture must preserve that source object without
silently dropping unknown fields so a later admission policy can make the
decision with complete evidence.

## Decision

### 1. Capture has one build-free MJS boundary

`framework/assignment-capture/assignment-capture.mjs` accepts
`kungfu.assignment-request/v1` through the repository-pinned Node entry. It has
no dependency on a compiled Kungfu artifact, Python binding, native runtime, or
journal. The request's `workDefinition` is an opaque JSON object: capture
validates canonical JSON but does not reinterpret, normalize away, or admit its
source-system fields.

The request root is SHA-256 over canonical JSON without a trailing newline.
The immutable request bytes and a separately rooted capture receipt live under:

```text
<data-home>/inbox/assignment-requests/sha256/<prefix>/<digest>/
  request.json
  receipts/sha256/<receipt-digest>.json
```

Repeated capture of the same request from the same resolved context is
idempotent. A distinct capture context writes a distinct receipt without
duplicating request bytes. Different bytes at an existing content-addressed
path fail closed.

### 2. Target selection mirrors capture-only workspace policy

Resolution order is exact:

```text
explicit --workspace / --home
  -> KF_WORKSPACE_ROOT / KF_HOME
  -> nearest existing project .kungfu or Git worktree root
  -> ~/.kungfu Home with association=unassigned
```

Only the last case is unassigned. Capture creates the required inbox path but
does not create `runtime/`, write a journal, attach an Initiative, admit or claim
an Assignment, or modify Git.

### 3. Expiry retires projection state; it does not delete evidence

Every request declares `retention.policy=explicit-expiry-retain-bytes-v1` and
an explicit timestamp or `null`. Cleanup is a two-step protocol:

1. the default command returns a content-addressed plan for requests expired at
   the supplied cut time;
2. execution requires `--execute --expected-plan-root <exact-root>` and writes
   `expiry-receipt.json` for each still-current candidate.

An expiry receipt removes the request from the active inbox projection. The
request and all capture receipts remain byte-for-byte present. Automatic
deletion, time-of-scan deletion, background cleanup, and physical garbage
collection are outside v1.

## Falsification and qualification

This decision is false if capture:

- requires compiled Kungfu artifacts;
- initializes a runtime or appends a journal;
- changes workspace fallback order or labels an explicit Home as unassigned;
- drops any source work-definition field during a parse/write/read round trip;
- produces a receipt without a verifiable semantic root;
- deletes or moves request evidence during cleanup; or
- executes an expiry plan without the exact current plan root.

Qualification uses a public-safe value projection with the exact top-level
field set of historical Atlas goal
`2026-07-21-kungfu-l3-initiative-assignment-schema`, target-resolution cases,
idempotent capture, and stale-plan/retained-byte expiry tests.

## Consequences

- Kungfu owns a durable capture boundary before it owns Assignment admission.
- Atlas can become a client without requiring its complete card schema to move
  into the L3 domain model in one step.
- Home remains a deliberate capture target rather than a semantic-write
  fallback.
- Admission, claim, orchestration, continuation, and physical retention remain
  separate successor decisions.
