# KF-ADR-019fbbe4-40c5-7c67-9ed2-910a65430ff7: Intel macOS is unsupported across the Kungfu product

- Status: accepted; implementation staged for protected delivery
- Date: 2026-08-01

## Context

Kungfu no longer has a supported Intel macOS product artifact. Retaining
launcher, bootstrap, cache, package, documentation, or source-fallback paths
for Darwin x86_64 would make an unsupported host look recoverable and can send
it toward nonexistent release assets. The earlier Qualified Assignment Core
design briefly described a fourth macOS x86_64 row, but that strategy was
withdrawn before its Kungfu implementation was promoted. Historical branches,
commits, captures, and closed pull requests remain evidence and must not be
rewritten to manufacture a zero-match repository.

This record amends only the active platform-matrix and fallback scope of
SHIFU-ADR-019fab1a-2853-737e-8c67-a9b1aa9035aa. Its artifact identity,
qualification, promotion, CAS, and exact-checkout rules remain in force.

## Decision

Intel macOS, identified as Darwin x86_64 or `darwin-x64`, is unsupported across
the entire Kungfu product. A host with that identity fails with the stable
`unsupported-host` diagnostic before Shifu or Kungfu selects, downloads,
builds, resolves, promotes, installs, or runs a product artifact.

The supported Qualified Assignment Core matrix is exactly macOS ARM64, Linux
x86_64, and Windows x86_64 with CPython 3.13. The wider product and libnode
release matrices may retain their independently qualified Linux ARM64 rows,
but none may contain a Darwin x64 build, verification, package, publication,
cache, installer, or availability row.

Repository validation classifies every retained Intel macOS reference as one
of four bounded categories: an explicit negative policy or test, immutable
historical evidence, upstream or third-party source text, or mechanically
required optional lockfile metadata. An unclassified reference fails source
qualification. The classifier is evidence about repository text; it cannot
grant platform support or authorize an artifact.

## Consequences

- Users and automation receive one deterministic unsupported-host outcome
  instead of a late 404, missing package, or accidental source fallback.
- macOS ARM64, Linux, and Windows behavior remains unchanged and must retain
  its existing native regression evidence.
- libnode removes Darwin x64 from build, verification, resolution, packaging,
  and publication authority while retaining the historical withdrawal line.
- Lockfiles may continue to name upstream Intel macOS wheels or optional
  packages when their package managers require complete upstream metadata;
  those entries are not product availability claims.
- Reintroducing Intel macOS requires a new accepted architecture decision,
  complete artifact and consumer qualification, and an explicit change to the
  fail-closed classifier. Adding a symmetric row or fallback is insufficient.
