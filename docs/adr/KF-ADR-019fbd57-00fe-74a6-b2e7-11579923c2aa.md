# KF-ADR-019fbd57-00fe-74a6-b2e7-11579923c2aa: Product Release Cut history is portable independently of caches

- Status: accepted
- Date: 2026-08-01

## Context

Product Release Cut, Cut Transition, installed-image, activation, rollback, and
update-outcome evidence already have native owners. Their current installed
layout is durable enough to roll back without a source archive, but Exit Bundle
did not expose that history as a typed portable member. Treating SemVer, channel
indexes, download archives, Shifu state, or an absolute `productRoot` as the
portable identity would make recovery cache-dependent or path-dependent.

The durable-history contract also requires unknown required history to fail
closed, public and `shifu-local` trust domains to remain distinct, and
interrupted migration to leave an unambiguous active product world.

## Decision

Add `product-release-cut-v1` as an Exit Bundle member whose identity is the
selected `releaseCutRoot` and whose content root covers a verified inventory of
Release Cuts, Cut Transitions, installed image bytes, selection receipts, and
Product update outcome receipts.

The member delegates validation to the existing Product Release Cut and native
installed-product owners. Full import runs Exit's isolated preflight, requires a
clean destination selection journal, recreates images under destination-local
paths, and records a new copy-forward activation receipt. The receipt binds the
source bundle, history, selected receipt, image, transition, update-receipt, and
trust-domain roots. It is persisted before `current.json`; retry after an
interruption publishes only the selection already bound by that receipt.

Mutable channel and download caches are excluded. A rollback coordinate is
re-rooted only when its exact predecessor image is included. Unknown feature,
entry, or receipt kinds reject before destination publication. This adapter is
composition and migration evidence, not a second release or installer state
machine.

## Consequences

Benefits:

- installed Product Release Cut history can survive cache deletion and clean
  copy-forward import without changing Release Cut identity;
- public and `shifu-local` trust evidence remains explicit;
- receipt-before-selection ordering makes interrupted activation recoverable;
- source and destination paths are never confused as the same live selection.

Costs and limits:

- full bundles contain installed product bytes and can be large;
- initial import intentionally requires a clean selection journal; merging two
  independently active product histories needs a future explicit protocol;
- legacy bootstrap-only state is rejected rather than guessed;
- this proves software continuity, not physical-media or off-host durability.

The decision is falsified if import needs a source cache, upgrades local trust
to public trust, publishes `current.json` before its receipt, silently accepts
unknown required history, or guesses a missing rollback image from a label.
