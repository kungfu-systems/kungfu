# KF-ADR-019f8c53-6105-71e5-8f34-53f2a81ee61c: Core Cut is domain-neutral and Work lifecycle shares one native waist

- Status: accepted; native authority membrane implemented for protected review
- Date: 2026-07-22
- Related: [KF-ADR-019f86da-4f90-7410-a3fc-f9cdeb55d2be](KF-ADR-019f86da-4f90-7410-a3fc-f9cdeb55d2be.md), [KF-ADR-019f86da-4f90-709e-8116-1c8ddf385fdf](KF-ADR-019f86da-4f90-709e-8116-1c8ddf385fdf.md), and [KF-ADR-019f87cb](KF-ADR-019f87cb-b4e7-7cda-80ec-be5aceb7b500.md)

## Context

`project.cut/v1` correctly commits software source, Xinfa Atlas, and Episode
evidence, but those required fields make it a software Domain Profile object.
Promoting that exact shape to Kungfu Core would make Git and repository
concepts mandatory for course production, research, media, or other Profiles.
At the same time, the Work lifecycle matrix had language-specific reachability
and no shared operation catalog at the existing `kungfu_get_api` waist.

## Decision

The new Core identity is `kungfu.cut/v1`, rooted by
`sha256-kungfu-cut-canonical-json-v1`. Its required fields are Profile identity,
parent Cut roots, sorted typed authority bindings, an admitted Episode delta,
protocol/schema/policy roots, explicit uncertainty, and the Cut root. Core does
not name Git, repositories, source trees, Xinfa, or software projects.

Domain Profiles own display names and binding types. The software-development
Profile displays a Core Cut as **Project Cut** and binds Git source projection,
Xinfa Atlas, and Kungfu Episode evidence. Course Production displays the same
Core object as **Course Release Cut** and uses course authorities without a Core
code path or schema exception. The product command is `kungfu cut`; SDK nouns
are `Cut`, `CutRoot`, and `CutReceipt`.

Existing `project.cut/v1` artifacts are immutable historical identities. The
software adapter produces a distinct `kungfu.cut/v1` root and an explicit
`kungfu.cut.migration-receipt/v1`. Failed migration returns diagnostics and
creates no new artifact. Rollback means reading the legacy bytes with their
original verifier; it never aliases, rewrites, rehashes, or reinterprets either
root.

The closed lifecycle inventory is projected from the operation matrix into
one `work_lifecycle` action over runtime-action ABI v1. C++, Node.js, Python, and
Rust receive the same generated catalog and operation-set root. This waist owns
discovery, routing, envelope validation, and fail-closed receipt admission. It
does not become a new Fact, Episode, Work Control, Profile, Git, Xinfa, or
Project Cut authority. A delegated mutation cannot report success until the
named authority supplies an exact root-bound receipt.

### Authority membrane closure

Every inventory row names exactly one native semantic owner and one native
interface. The four language SDKs expose both ergonomic request builders and a
raw byte transport. Builders require explicit `input` and `execute` values;
the raw transport does not parse, default, filter, reorder, or reinterpret the
request or response. Unknown operation identifiers reach the native waist and
return `unsupported` with a stable reason code. Missing fields, `null` where an
object is required, and non-boolean execution intent are rejected rather than
defaulted.

The runtime reports `available`, `degraded`, `unavailable`, or `unsupported`
without client-side compatibility remapping. A route that has not executed its
named authority reports `projected` and `authorityExecuted: false`; even a
structurally plausible delegated receipt cannot be admitted by this routing
layer. Pure-Python semantics remain available only behind an explicit
`conformance=True` oracle and are never a production fallback.

The matrix reconciles the layered API, portable format contract, primitive
catalog, and native Work journal as separate views of the same authority
boundary. The native Work journal owns append and replay through the
`work_journal` runtime action and now also executes the six public
`work.lifecycle.work.*` routes through one co-located lifecycle adapter. The
adapter derives canonical request, journal, item, bundle, and receipt Roots in
C++; mutating execution requires exact request and predecessor Roots, and no
successful response exists without a native append receipt.

`inspect` folds recognized Work events while retaining exact envelope bytes
and unknown records. `export` emits an opaque versioned bundle of those exact
ActionEnvelope bytes; `import` prevalidates the complete bundle, requires an
empty destination, and replays the bytes without decoding them into a second
authority format. C++, Python, Node.js, and Rust remain byte-preserving
projections over the same runtime-action ABI. Qualification exercises all six
operations, stale authority bases, receipt-backed mutation, and a future
unknown ActionEnvelope export/import round trip.

The lifecycle operation matrix and its four-language SDK projections are now
materialized from the authoritative native-operation and Project Cut catalogs.
Generated rows remain checked artifacts rather than a second semantic source:
the generator fails on duplicate, missing, or reordered authority identities,
and source acceptance verifies that the checked projections are current.

PR #1718 reuses this implemented waist for KFX mutation authorization rather
than creating a KFX-private lifecycle authority. Before side effects, a named
Work and purpose-bound Warrant bind the Core-recomputed Release Passport,
policy, capability, approval, package/dependency, receipt-dependency, and
expected-Cut roots. After apply, Work settlement, Warrant consumption, Episode,
Settlement, and Cut receipts preserve the exact mutation outcome. This is an
additional consumer of the implemented Work/Cut authority; it does not reopen
or weaken the ADR's closure.

PR #1728 carries the same authority roots into an explicit capability grant and
requires each KFX host launch to reauthorize the exact Work/Warrant, prior Cut,
package, policy, grant, revision, generation, approval, and confinement
boundary. KFD eligibility, first-party identity, and Product System metadata do
not substitute for that authority. This extends the KFX consumer across the
runtime edge without making KFX history, host projections, or Product metadata
a second Work/Cut authority.

PR #1744 removes every identity- or origin-derived shortcut around that
implemented waist. First-party/System/Product System labels, bundle paths,
installer origin, and KFD status cannot create Work, consume a Warrant, select
a grant, or weaken confinement. The KFX contract and every host instead carry
the exact existing Work/Warrant, Passport, policy, grant, Cut, generation, and
isolation roots. This preserves the implemented Cut/Work authority unchanged;
KFX remains a consumer and Product System remains inert assembly metadata.

## Consequences

- Third-party Profiles can create and verify Cuts without adding Core symbols.
- `work.lifecycle.cut.*` is the sole pre-stable Core operation namespace;
  `work.lifecycle.project-cut.*` is not retained as an alias.
- Four-language parity proves the shared envelope, operation set, byte encoding,
  error boundary, and authority routing. It does not claim that an unavailable
  Domain Profile operation has become available.
- Installed qualification mutates missing, null, false, unknown, and reordered
  request fields across all four SDKs and compares exact native response bytes
  and error classes.
- Native ABI qualification executes Work inspect, create, update, transition,
  export, and import end to end, including preservation of an unknown future
  ActionEnvelope and its record Root.
- The KFD-2 Release Passport claim carries the matrix and its residual risks;
  it cannot upgrade `projected`, `degraded`, or `unavailable` rows to native
  semantic success.
- GUI and TUI discovery can render the active Profile's display name while
  preserving `Cut` as the stable object identity.
