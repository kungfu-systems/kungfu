# KF-ADR-019f86da-4f90-7272-b883-cb90fc4613b1: Project Cut history uses explicit rooted bindings outside the Cut preimage

- Status: accepted; implementation implemented by PR #972
- Date: 2026-07-15
- Category: Project Cut / Git history / publication reconciliation
- Related: [KF-ADR-019f86da-4f90-77d5-a9ce-e7c798e3a623](KF-ADR-019f86da-4f90-77d5-a9ce-e7c798e3a623.md),
  [KF-ADR-019f86da-4f90-7410-a3fc-f9cdeb55d2be](KF-ADR-019f86da-4f90-7410-a3fc-f9cdeb55d2be.md),
  and [KF-ADR-019f86da-4f90-709e-8116-1c8ddf385fdf](KF-ADR-019f86da-4f90-709e-8116-1c8ddf385fdf.md)

## Context

A semantic Project Cut can be published by more than one Git commit, and one
commit can publish more than one Cut or admitted Episode. Rebase, amend,
squash, and cherry-pick can change Git object identity without changing a
sealed semantic root. A merge, revert, or recovery can instead introduce a
successor Cut whose decisions require independent Episode evidence. Git
topology alone cannot distinguish these meanings or become causal authority.

## Decision

### 1. History observations are separate rooted facts

`project.cut.history-observation/v1` records a Git commit, tree, ordered parent
commits, declared operation, Cut and Episode roots, prior observation roots,
and optional ref compare-and-swap evidence. Its `observationRoot` covers that
canonical object. It is deliberately outside `project.cut/v1`; Git object ids,
ref names, and history operations remain excluded from the frozen Cut root
preimage.

An observation reports either `qualified` or `incomplete` with stable
diagnostics. It grants no Git, Atlas, Episode, Mission, or Go authority.

### 2. Rewrite and republish claims require prior rooted bindings

Rebase, amend, squash, and cherry-pick use the `same` relation and must name
qualified prior observations with the exact same Cut-root set. A branch
publication follows the same rule and additionally observes the exact ref
target. Missing prior evidence, semantic-root drift, or lost ref compare-and-
swap fails visibly. The protocol does not infer an operation from a diff or
commit message.

### 3. Successors bind semantic parents and independent Episodes

A merge observation must name qualified observations for the exact Git parent
commits. Its output Cut declares the prior Cut roots as semantic parents and
admits a separately rooted Integration Episode. Revert and recovery likewise
publish successor Cuts and admit a resolution Episode. Git parent order is
preserved as a publication fact but never interpreted as causal order.

An empty commit can be observed only when its tree equals its single parent's
tree and it claims no new Cut or Episode.

### 4. Reconciliation is N:M and lock-free across observations

Reconciliation builds independent Cut-to-commit and Episode-to-commit maps.
Prior bindings remain retained as `superseded`; unreachable bindings are
`orphaned` unless superseded or explicitly archived. Recovery publishes a new
successor observation instead of rewriting sealed history.

There is no repository-global or Episode-global history lock. Independent
worktrees qualify independently; ordinary Git ref compare-and-swap exposes
contention at the affected ref.

## Falsification and acceptance gates

- Every admitted history operation is exercised in disposable Git repositories.
- Rewrite operations preserve exact Cut roots and fail without prior bindings.
- Merge parent commits, semantic parent Cuts, and the Integration Episode must
  agree exactly.
- One commit can publish multiple Cuts and one Cut can map to multiple commits.
- One Episode can map to multiple commits without creating a global lock.
- Ref contention, missing priors, orphaning, archive, and recovery are visible.
- The frozen Project Cut and settlement roots remain byte-for-byte unchanged.

## Non-claims

This decision does not reconstruct user intent from Git, make ancestry causal
authority, mutate refs, serialize independent Episodes, erase superseded
observations, or change any existing Project Cut, Xinfa Atlas, or Episode root.
