# KF-ADR-019fbee3-68b1-7154-a6d2-860b9506dccd: Durable history qualification is a bounded cross-domain proof

- Status: accepted
- Date: 2026-08-01

## Context

The individual Work/Agent, Project Cut/Dogfood, Product Release Cut, and Exit
History slices each retain their own authority and focused qualification. A
user-facing protection promise still needs one falsifiable answer to a broader
question: do all declared entrypoints route to those same owners, and can exact
history survive clean import, supported migration, interruption, cache or
worktree loss, rollback, unknown members, and garbage collection without a
warm UI or cache?

A single physical store or aggregate event log would answer that question by
creating a new authority. A static matrix without executed campaigns would not
prove recovery. Conversely, a successful local gate cannot support claims
about an installed product, stable release, off-host copy, physical device
loss, or platforms whose packaged artifacts were not executed.

## Decision

Add one source-qualification composition contract and Shifu gate. The matrix
covers GUI, TUI, CLI, native and managed Agents, Skill/KFD, Atlas dogfood,
Shifu, Project Cut, Product Release Cut, update/release, and Exit Bundle, while
each row names its existing authority route and proof source. The gate executes
the owner-domain contract checks plus a disposable failure corpus for full and
thin import, predecessor reading, interrupted operations, cache and worktree
loss, rollback, unknown members, and GC.

After the campaigns pass, a stdout-safe receipt binds the exact Git revision,
source closure, native artifact, contract, entrypoint matrix, campaign corpus
and results, bounded claim, and required review criteria under canonical roots.
The receipt is evidence only. It cannot replace any member-domain root or the
independent native Assignment review required before close and seal.

The qualified claim is deliberately narrow: exact-source and exact-artifact
local functional software continuity. Long-duration soak, independently
verified off-host backup/restore, and packaged-platform expansion remain
explicit deferred work. Real user homes are never qualification inputs.

## Consequences

Benefits:

- one gate catches cross-entrypoint drift and hidden loss across all delivered
  data-protection slices;
- clean recovery and failure diagnostics are bound to executable owner tests,
  not prose or UI state;
- a retained receipt can be compared exactly after source or artifact drift;
- thin, installed, release, off-host, and platform claims remain visibly
  separate from source qualification.

Costs and limits:

- the aggregate gate is slower than a single domain check because it executes
  a focused cross-domain campaign;
- every new protected entrypoint or critical failure class must extend the
  matrix and corpus;
- source qualification must be repeated for a changed source/artifact root and
  cannot be relabeled as packaged-product or release evidence.

The decision is falsified if any entrypoint derives authority independently,
thin loss can appear complete, a recovery test needs the original UI, worktree,
or cache, the receipt omits an exact source/artifact/campaign/review binding, or
the bounded claim is used to assert off-host, physical-media, installed,
stable-release, or unexecuted-platform protection.
