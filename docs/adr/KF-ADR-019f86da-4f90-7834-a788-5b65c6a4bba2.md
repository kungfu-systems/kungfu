# KF-ADR-019f86da-4f90-7834-a788-5b65c6a4bba2: KFD-7 v1 exposes cooperative cancellation and process-bounded deadlines honestly

- Status: accepted; implementation staged pending supported-platform requalification
- Date: 2026-07-21
- Extends: [KF-ADR-019f86da-4f90-7b96-bc7d-4555833303eb](KF-ADR-019f86da-4f90-7b96-bc7d-4555833303eb.md)

## Context

The v1 C ABI allocated `KF_TIMEOUT` and retained `default_timeout_ms`, but no
runtime path returned the status. Discovery nevertheless described timeout as
a declared bounded-operation outcome. Cancellation was real at admission, but
the only data-dependent loop—the journal batch reader—did not poll the latched
request after admission. Embedders therefore could not distinguish implemented
behavior from reserved layout, or safely design a hard-deadline supervisor.

A thread cannot safely unwind an arbitrary in-flight C++ native call. It may be
holding locks, borrowed mmap pages, or storage state whose outcome is already
durable. Returning `KF_TIMEOUT` after such a call completes would also be
dishonest: a mutating operation may have occurred even though the caller sees a
timeout. V1 has neither a per-call deadline nor a universal operation id and
reconciliation receipt that could represent that outcome.

## Decision

### 1. Timeout is reserved in ABI v1

`KF_TIMEOUT` keeps numeric value 11 and `default_timeout_ms` keeps its struct
position, so layout and status numbering remain compatible. Discovery, the
error dictionary, the installed contract, and the Release Passport all say
that no v1 operation returns `KF_TIMEOUT`. Callers set `default_timeout_ms` to
zero. A future executable deadline requires a separately versioned operation
contract with per-call budget and outcome/reconciliation semantics.

### 2. Cancellation is an admission fence, not thread preemption

All admitted entry points check the owner thread and latched cancellation
before their first caller-visible or native side effect. Control and cleanup
operations deliberately bypass cancellation so a caller can inspect errors,
release tokens, close child handles, reset cancellation, and close the context.
`context_request_cancel` remains the sole cross-thread-safe context operation.

An admitted one-shot discovery or storage call runs to return. Cancellation
requested during that call is observed by the next admission. No foreign thread
may close or destroy the context to force an unwind.

### 3. Stream batches checkpoint every 32 frames

The batch reader polls the request at frame boundaries. At the first checkpoint
with no collected frame it returns `KF_CANCELLED` and no batch. Once frames have
been collected it returns `KF_OK` with a valid partial, token-bounded batch. The
request remains latched, so the next admitted operation returns `KF_CANCELLED`
until the owner thread resets it. Returning `KF_OK` for a partial batch preserves
v1's rule that output is valid only on success; it does not invent a valid-output
exception for error statuses.

### 4. A worker process is the minimum discardable unit

An HA embedder owns the hard deadline outside the process hosting the context:
deadline, cooperative cancel, termination request, grace period, forced process
termination, reopen, then recovery or escalation. POSIX supervisors normally
use `SIGTERM` then `SIGKILL`; Windows uses the platform-equivalent process
termination mechanism. The contract is about the state transition, not a
portable signal spelling.

Process-local handles, borrowed pages, and result tokens are lost after exit.
Kungfu append-only journal, Episode, and receipt-backed storage evidence can be
reopened and checked through its operation-specific fencing and recovery paths;
this is not a generic success guarantee. Arbitrary extensions and third-party
side effects are unknown unless the operation declares its own idempotency key,
receipt, and reconciliation contract.

## Rejected alternatives

- Checking elapsed time only after a native call: rejected because it can hide
  a completed side effect behind `KF_TIMEOUT`.
- Treating `default_timeout_ms` as a context-age deadline: rejected because it
  is not an operation timeout and would surprise existing callers.
- Returning `KF_TIMEOUT` with a partial batch: rejected because v1 has no rule
  that makes output valid on an error status.
- Closing a context from the cancelling thread: rejected because context and
  child ownership is thread-affine and destruction cannot safely preempt native
  state.

## Consequences

The contract becomes narrower but truthful. Cooperative latency in the stream
loop is bounded by 32 frames; single-shot native call latency remains bounded
only by the operation implementation and the outer process watchdog. The
operational contract and conformance corpus are installed beside the ABI. The
previous three-platform qualification remains historical evidence; this change
must be requalified before the Release Passport returns to `passed`.
