# SHIFU-ADR-019fab1a-2853-737e-8c67-a9b1aa9035aa: Qualified Assignment Core artifacts bind identity, qualification, and promotion authority

- Status: accepted; implemented, qualified, independently reviewed, and merged in PR #1808
- Date: 2026-07-29

## Context

Assignment Core builds are expensive enough to reuse, but a transport cache hit
does not prove that native bytes belong to the current source, platform, Python
ABI, toolchain, dependency lock, or protected delivery candidate. Rewriting
producer metadata to look current would erase the distinction between exact
identity and an independently established equivalence. Copying payloads
directly into a runnable target also leaves traversal, symlink, partial-write,
and dirty-checkout ambiguity.

The contract must remain useful when cache providers are unavailable. GitHub
Actions cache and workflow artifacts can disappear, be evicted, or be replaced
without changing the correctness of a merge. Shifu, Buildchain, CAS,
Assignment, qualification, and promotion therefore need explicit and
non-overlapping responsibilities.

## Decision

Shifu defines two strict v1 JSON schemas under `docs/shifu/schema/`: one
qualified Assignment Core artifact manifest and one qualification receipt. All
objects reject unknown fields and unsupported major versions. Roots are
SHA-256 over UTF-8 JSON with recursively lexicographic object keys, original
array order, `JSON.stringify` scalar encoding, and no insignificant whitespace.

The manifest binds:

- producer repository, commit, and source-tree root;
- target repository and commit;
- exact native input, operating-system, architecture, Python ABI, build
  profile, toolchain, and dependency-lock identities;
- versioned Shifu and Buildchain contract roots;
- a sorted, unique set of regular files and safe relative symlinks with exact
  path, size, digest, and mode;
- the manifest, artifact, qualification, and promotion-authority roots; and
- clean-checkout, outside-target staging, atomic replacement, and
  non-runnable-partial-state requirements.

Exact mode requires producer and target commits to be identical. Explicit
equivalence requires distinct identities plus an immutable equivalence receipt;
producer metadata is never rewritten. The qualification receipt rebinds the
manifest and artifact roots, records all mandatory checks as passed, and binds
one active, time-bounded authority for the exact protected-development target.
Missing, stale, or ambiguous promotion authority fails closed.

Shifu owns schema, canonical roots, verification, and safe publication
semantics. Buildchain supplies exact build and delivery identities. Assignment
supplies producer and target intent. CAS retains verified bytes by content root.
Qualification proves one manifest/payload pair. Promotion authority selects
one currently reusable candidate. Cache and workflow artifacts transport bytes
only and never establish identity, qualification, or promotion authority.

## Consequences

Consumers can reject tampered payloads, traversal, unsafe symlinks, platform or
ABI drift, build/toolchain/lock drift, dirty targets, producer impersonation,
and stale or ambiguous selection before publication. Cache loss or rejection
falls back to a current-source build, so transport availability cannot affect
merge correctness.

The first slice intentionally defines and verifies the contract without
claiming a production payload, upload path, CAS materializer, cross-platform
qualification, or stable compatibility line. A producer/promotion follow-up
must emit the exact schema, roots, and protected delivery evidence and prove
atomic consumer behavior with real native payloads before reuse may become a
blocking build path.
