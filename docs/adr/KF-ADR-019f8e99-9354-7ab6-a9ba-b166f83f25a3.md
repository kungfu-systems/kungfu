# KF-ADR-019f8e99-9354-7ab6-a9ba-b166f83f25a3: Workspace Federation and Assignment Graph preserve one authority per workspace

- Status: accepted; implementation and qualification staged
- Date: 2026-07-23

## Context

Kungfu already has one Home workspace, project-local `.kungfu` data homes,
bounded GUI recents, Initiative/Assignment facts, and Project Cut settlement.
Those pieces do not by themselves form a work federation. Absolute paths still
participated in project identity, `parent_assignment_id` and `depends_on` were
unqualified local strings, and a caller outside a project could not enumerate
known work without choosing one journal as a false global database.

A federation must not weaken the existing authority boundary. A project move,
another machine's path, or a Git worktree lifecycle must not change semantic
object or relation identity. Home must not receive duplicate project facts.
Cross-workspace delegation cannot pretend that two journals commit atomically.

## Decision

### 1. Workspace identity is portable; paths are locators

Each initialized workspace owns
`<data-home>/workspace-identity.json`, whose semantic root binds only schema,
workspace kind, and a generated workspace key. Home has a deterministic Home
identity. Before an uninitialized project performs a write it is only a
`locator-candidate` and cannot mint an Assignment WorkRef. Absolute paths,
user/device names, branches, and worktree coordinates never enter portable
roots.

The machine-local Workspace Locator Catalog is distinct from bounded GUI
recents. It records every explicit selection and successful write, including
unqualified candidates, but owns no Initiative or Assignment facts. Verify,
bounded rebuild, and exact-identity rebind never scan the filesystem and never
repair a workspace journal implicitly. Catalog loss reduces discovery only.

### 2. Assignment graph edges use exact owning-workspace references

`kungfu.assignment-graph.work-ref/v1` binds an owning workspace identity root,
object kind, subject, version root, and component cut root. A local parent or
dependency shorthand is resolved exactly once before Assignment admission and
stored as a WorkRef. An unresolved string fails admission. A project
Assignment may instead bind the Home Initiative's external WorkRef; it does not
create a mutable project copy of that Initiative.

The v1 relation vocabulary and its directed, symmetric, transitive, revocable,
and acyclic properties are frozen in
`framework/workspace-federation/workspace-federation.contract.json`.
Acyclicity is qualified per relation type. Descriptive symmetric graphs remain
legal.

### 3. Cross-workspace handshakes are independent facts

Delegation offer, destination acceptance, source observation, child
contribution, parent admission, assessment, and decision each produce a
content-addressed, retryable event routed to the endpoint's owning workspace.
Predecessor and evidence roots make partial progress visible and resumable.
There is no distributed transaction or inherited Warrant, trust, acceptance,
permission, completion, or Project Cut authority.

Graph events use a distinct record vocabulary on the existing sealed
Initiative/Assignment v1 claim surface. Adding a new fact surface to that
already-installed contract world would change its register in place and is
therefore forbidden without an explicit contract migration.

### 4. Federated reads preserve component truth

`local`, `related`, and `all` queries return the same machine contract to human
and agent surfaces. Each component retains its own cut, proof root,
availability, staleness, and failures. Unavailable Catalog entries and
unresolved references remain visible. Reads never create Home, initialize a
project, import evidence, establish relations, or claim an atomic global cut.

The global projection composes one authority-qualified identity index before
resolving references. Observations fold only when an exact shared version root
proves that they are replicas. Equal human labels under distinct authorities
remain distinct; divergent versions under one authority remain a conflict.
The default human view shows one row per canonical Work object, while component
observations, replicas, label collisions, conflicts, exclusions, and unresolved
references remain available through progressive detail and the JSON envelope.

Catalog membership has an explicit local lifecycle. Active entries are
required by default; retired, test-only, and quarantined entries stay retained
and counted but are excluded by declared policy. Lifecycle maintenance is
exact-entry and dry-run-first, binds the observed Catalog cut, emits a durable
before/after receipt, and never rewrites a workspace authority. Execution may
bind the transition timestamp and expected plan root from that dry run; a
recomputed-plan mismatch fails before writes. A Catalog change during a query
yields a marked retry result rather than a hybrid view.

Global completion remains false until an independent continuation Decision
accepts the result and the applicable Project Cut root plus settlement receipt
are evidenced. Execution exit, stage-ready, claim, review, decision, and
pending settlement remain distinct Portfolio states.

The installed human help tree and Agent CLI Catalog are generated from the same
surface contract. Product distribution fails closed when their contract roots
drift, and Buildchain KFD evidence pins the regenerated Catalog and registry so
the global Work surface cannot ship with a stale Agent projection.

## Consequences

- A repository can move or be recreated as a worktree without changing its
  workspace identity or Assignment graph roots, provided its portable identity
  material moves with it.
- Duplicate local Assignment IDs in different workspaces are unambiguous
  because the workspace identity root is part of every graph reference.
- Discovery is bounded by explicit Catalog evidence; v1 intentionally does not
  discover arbitrary sibling repositories or remote machines.
- Canonical Work count and component observation count are intentionally
  different measures. Strict mode also reports replicas, conflicts, stale,
  unavailable, excluded, unresolved, proof, and zero-write evidence rather than
  using a clean display to erase degraded truth.
- Cross-machine locator exchange and historical migration require later,
  explicit protocols. Existing uninitialized workspaces qualify their identity
  on first semantic write; no big-bang history rewrite is performed.
- The 2026-07-23 qualification fixture uses exact clean Git snapshots labelled
  `kungfu-trader/action-approve` and `kungfu-trader/qlib`. Those labels preserve
  the historical evidence identity; they are not current ownership coordinates
  or recommended clone targets. The fixture proves the federation protocol
  against heterogeneous source trees without writing their working copies.
  Persistent in-place adoption remains rollout evidence, not a claim of this
  ADR.
- The decision is falsified if a federated read writes any queried workspace,
  a path enters a portable WorkRef/relation root, a graph event is written to
  the wrong endpoint, a Catalog row becomes fact authority, or a global result
  is presented as one atomic cut.
