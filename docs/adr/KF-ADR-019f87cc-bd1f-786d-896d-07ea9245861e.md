# KF-ADR-019f87cc-bd1f-786d-896d-07ea9245861e: Assignment orchestration state is fact-backed and portably sealed

- Status: accepted; implementation and qualification staged
- Date: 2026-07-22
- Category: Work Control / Assignment orchestration / settlement
- Related: [KF-ADR-019f86da-4f90-7a57-a680-9739f5e67173](KF-ADR-019f86da-4f90-7a57-a680-9739f5e67173.md),
  [KF-ADR-019f8759-ab29-7627-bc04-6aba547ea45f](KF-ADR-019f8759-ab29-7627-bc04-6aba547ea45f.md),
  and [KF-ADR-019f878c-5480-7890-bc64-9b2aab7e9aa5](KF-ADR-019f878c-5480-7890-bc64-9b2aab7e9aa5.md)

## Context

Capture deliberately creates no Assignment authority. After admission, an
agent still needs one product-owned sequence for claim, kickoff, stage,
Completion Claim, independent review, continuation decision, and closeout.
Keeping that sequence only in an Atlas card or mutable worktree file would make
Atlas a hidden authority and would lose settlement evidence when a worktree is
removed.

## Decision

Kungfu Work Control owns the append-only phase fold:

```text
admitted -> claimed -> executing -> stage-ready
  -> completion-claimed -> independently-reviewed -> continuation-decided
```

The first two transitions are explicit Assignment orchestration facts.
Completion, review, and decision phases derive from their existing admitted
facts, so the phase machine does not duplicate those authorities. Every CLI
response includes structured `next_actions`; run and closeout gates fail closed.
The gate includes an `atlas_compatibility` projection with the exact Atlas v1
field set while Kungfu remains the source of the underlying state.

At settlement, Kungfu writes a self-contained canonical snapshot under the
shared Git common directory when the workspace is a Git worktree:

```text
<git-common-dir>/kungfu/assignment-states/sha256/<prefix>/<digest>/
  state.json
  receipt.json
```

The common directory is resolved from the worktree `.git` file and its
`commondir` declaration; it is not inferred from a mutable branch name. A
non-Git workspace falls back visibly to
`<workspace>/.kungfu/assignment-states/`, and its receipt reports that it is
not worktree-deletion-safe.

Execution requires the exact planned state root. The snapshot contains no
runtime or worktree path and remains verifiable after the live runtime and
source worktree are gone. It is a portable settlement witness, not a mutable
second state authority.

The same orchestration surface accepts an explicitly selected logical Home
Workspace. Home is resolved through the public workspace resolver and carries
stable identity `home`; commands do not hard-code its physical path. Read-only
`status` and `gate` require an initialized target and do not initialize or
repair it. Fact-bearing admission, claim, transition, review, decision, and
seal operations continue through the shared write-intent gate.

Admission has two provenance-qualified execution forms:

- source Shifu requires a compiled binding whose build-info revision is the
  pristine current checkout; and
- an installed archive or Desktop companion requires the binding to live under
  its declared runtime root, with matching build-info and release-manifest
  source revisions and a declared runtime artifact digest.

The installed runtime carries the exact Work Control Profile used by the
Assignment actions. It therefore neither reads nor builds a source checkout.
Foreign bindings remain a named degraded override and never become installed
product authority.

Cross-workspace parent/child coordination uses
`kungfu.assignment-orchestration.cross-workspace-binding/v1`. The canonical
binding contains only stable Home/project workspace identity, Initiative and
Assignment identity, relationship type, exact state/Cut/evidence/request roots,
and admission receipt roots. Each endpoint admits the same binding root and
writes its own content-addressed local receipt. Physical paths are locators in
the command result, not binding identity. The binding and either endpoint
receipt remain independently verifiable without a live runtime; neither action
copies child facts into Home or introduces a second Assignment state writer.

## Falsification and qualification

This decision is false if a phase can skip its predecessor, a run gate passes
without a live execution lease, closeout passes before a continuation decision,
a response omits `next_actions`, seal execution accepts a stale root, or sealed
bytes require the original runtime to verify. It is also false if an installed
CLI requires a source checkout, a read-only query initializes Home, a binding
uses a mutable path as identity, one endpoint can admit a different binding
root, or an endpoint receipt survives tampering.

## Implementation evidence

- [PR #1720](https://github.com/kungfu-systems/kungfu/pull/1720) stages
  expected-root-fenced family planning, transition, status, coverage, and
  residual continuation on the existing Assignment orchestration authority.
- [PR #1838](https://github.com/kungfu-systems/kungfu/pull/1838) binds the
  accepted Assignment discovery cut to retained organization dogfood,
  minimum-closure, portable-seal, worktree-deletion, and tamper evidence as a
  non-shipped KFD-5 adopter candidate. Its passed Buildchain gate remains
  non-qualifying and non-self-certified.

## Consequences

- Atlas can consume the same gate geometry without owning the state machine.
- Worktree deletion no longer deletes the only go settlement witness.
- Completion review and continuation retain their existing independent facts.
