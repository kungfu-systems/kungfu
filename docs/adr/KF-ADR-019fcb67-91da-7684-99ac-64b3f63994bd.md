# KF-ADR-019fcb67-91da-7684-99ac-64b3f63994bd: Runtime execution surfaces carry explicit provenance

- Status: accepted; implementation staged
- Date: 2026-08-04

## Context

Kungfu can execute an operation through an installed product, a source
checkout, or a composition that deliberately joins both. Those routes have
different availability, build, portability, and trust properties. Inferring a
route from the current directory, an import path, or a missing executable can
silently turn installed-product work into source work and make later evidence
misstate what actually ran.

Platform, runner, and product variants need one shared mechanism for recording
this distinction. A Linux, Windows, macOS, hosted, JIT, or persistent adapter
must not create a parallel authority merely because its executable discovery
or lifecycle differs. Assignment and Work roots also remain native authority;
runtime-surface selection cannot manufacture or widen them.

## Decision

Kungfu defines one governed runtime-surface provenance contract with exactly
three surface kinds:

1. `installed-product` identifies execution through assembled or installed
   Kungfu bytes and binds the executable, version, portable bundle, and
   qualification evidence that were actually selected.
2. `source-checkout` identifies execution through an exact Git checkout and
   binds its commit, tree, Shifu entry, and build evidence.
3. `hybrid-boundary` identifies an explicit composition whose participating
   installed and source evidence remains separately visible.

Every governed operation resolves a declared candidate through the same
authority and emits a content-rooted receipt. Receipt verification repeats the
contract checks without guessing missing data. Unsupported candidates,
ambiguous authority, root drift, and silent source fallback fail closed.
Platform and runner adapters may discover or launch a compatible candidate,
but they cannot define a fourth surface, rewrite the receipt, or become a
second selection authority.

Assignment request, Work definition, and Work roots are optional bound inputs,
not derived outputs. A missing native root stays `null`; source or product
qualification cannot invent it. Dogfood records the resolved surface and may
open an owned Issue only through the existing Finding policy. TUI and GUI are
observers of the same receipt rather than independent selectors.

The executable contract is
`framework/core/runtime/kungfu-runtime-surface.contract.json`, with Python and TUI
consumers plus `scripts/qualify-runtime-surface.mjs`. The qualification matrix
must cover installed Assignment capture, source build and test, installed
portable-bundle use, actual Dogfood surface, hybrid context consumption, and
installed seal verification. Each row is admitted only from rooted evidence
emitted by the real consumer probe; resolver-only rows are non-qualifying. The
hybrid context row also binds a production TUI diagnostic observation that has
passed the Kungfu authority verifier.

## Consequences

Runtime location becomes auditable without coupling semantic Work identity to
host paths. New operating systems, runner lifecycles, Agent providers, and
product shells can reuse the same three surfaces while keeping their adapter
differences explicit. Portable bundles can explain an installed product, and a
source checkout can remain a distinct authoring or recovery route.

The cost is that callers must provide coherent candidate evidence and handle a
denial instead of relying on implicit fallback. Generated catalogs, KFD
evidence, documentation bundles, and observer projections must remain aligned
with the single contract. Local qualification proves only the exact source and
assembled product it names; it does not prove publication, release
qualification, or unexecuted platform products.

This decision is falsified if an operation can execute without a verifiable
surface receipt, if a platform or runner defines parallel selection semantics,
if a missing native root is inferred, if hybrid execution collapses its two
evidence sources, or if source availability silently substitutes for an
installed product.
