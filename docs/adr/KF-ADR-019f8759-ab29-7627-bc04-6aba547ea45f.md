# KF-ADR-019f8759-ab29-7627-bc04-6aba547ea45f: Initiative and Assignment are the canonical L3 control-plane terms

- Status: accepted and implemented by PRs #1200, #1404, and #1720; the
  consumer-project compatibility closure is implemented by PR #2825.

## Context

Kungfu needs a self-contained vocabulary for continuing intent and bounded
delegated responsibility. Consumer project workflows must not determine Kungfu
command names, schemas, storage paths, or object identities.

## Decision

The current contract world is `kungfu.initiative-assignment`, version `1`, with
these fact surfaces:

- `kungfu.initiative-assignment.initiative`;
- `kungfu.initiative-assignment.assignment`; and
- `kungfu.initiative-assignment.completion-claim`.

Initiative and Assignment are Domain Profile records. They do not add an Action
Geometry role and do not change the generic KFD-7 `pursuit` or Xinfa `atlas`
roles. Records and receipts use canonical JSON preimages; transport bytes do not
become semantic identity.

Only the current world, schemas, commands, and readers are public. Kungfu does
not install consumer-specific aliases, translation modules, predecessor readers,
or alternate writers. External coordinators integrate through the neutral
Assignment Runtime and Work Control contracts.

## Falsification and qualification

The decision is false if a consumer project identifier changes a Kungfu public
name, if more than one writer can author Assignment state, if a non-current
schema is accepted, or if Initiative/Assignment changes the generic Pursuit or
Xinfa Atlas role contracts.

Qualification requires Profile source validation, current-schema contract
materialization, native Assignment lifecycle tests, generated CLI/catalog
parity, installed-product inspection, and zero-residue scans.

## Consequences

Kungfu has one L3 vocabulary and one authority path. Historical repository
commits remain available through Git, but current source, documentation,
fixtures, products, and runtime carry no predecessor compatibility surface.
