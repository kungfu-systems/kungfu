## Context

Kungfu already has the pieces of an agent-work product loop, but they are not
yet one product contract:

- Work Control renders Mission/Go, Cost/State/Proof, public Profile intents,
  queries, assessments, and external projections.
- the Terminal KFX owns PTY and isolated tmux/direct lifecycle, durable adoption,
  multiple panes, and per-session windows;
- `kungfu managed-run` launches Codex or Claude as a one-shot structured-output
  command and injects Skill context;
- the Agent Pack exposes the KFD-3 context/capability/Profile surfaces; and
- external report/receipt remains a valid way to supply honestly labelled work
  Facts without using a Kungfu-managed process.

The current Terminal launcher is nevertheless a hard-coded inbox of prompts.
It does not represent the user's installed Codex/Claude launch methods, a stable
work-bound console, multiple physical attempts, or a versioned discovery
envelope. Work Control's declared Profile actions also stop at the common
lifecycle runner; domain mutation still uses compatibility APIs. Joining the UI
without first joining these contracts would create a private GUI workflow and a
second work authority.

## Decision

### 1. Keep work authority and execution placement independent

Work authority is either `kungfu-native` or an explicit external projection.
Execution placement is either `kungfu-console` or `external-report`. A Kungfu
Console does not silently acquire write authority over Atlas or another source.
An authority migration records source root, cut, new identity, and a migration
receipt; long-lived dual write is forbidden.

### 2. Use generic work and console identities

The Console Runtime consumes `kungfu.work-ref/v1`, not Mission/Go fields. A
stable `WorkConsole` normally binds one delegated-work entity and owns one or
more `SessionAttempt` records. Restart, recovery, or runtime-profile changes
create a new attempt without creating a second work item or pretending that a
new process is the old process.

A workspace assistant is the explicit unbound variant. It may create work
through public Profile actions, but it never changes its own binding implicitly.

### 3. Make Agent Runtime Profiles machine-global configuration

Codex and Claude are providers. The executable, argv, bootstrap adapter, cwd
policy, backend default, and verification observation form
`kungfu.agent-runtime-profile/v1`. The catalog and default live in the global
Kungfu config under `~/.kungfu-config`; workspace Console identity and
presentation live in the journal-backed runtime ConfigStore. Executable paths,
ambient secret values, and live processes are never portable work data.

Discovery is bounded to PATH and explicit known executable locations. It may run
a bounded version probe, but it must not read provider auth, cookies, keychains,
session databases, billing state, or private logs. Normal launch uses executable
plus argv without a shell. Shell mode is an explicit, visibly riskier profile.

### 4. Separate Console identity, process lifecycle, and presentation

Tabs, up-to-three-way split, bottom assistant drawer, and detached OS windows
are references to a Console. Closing or moving a presentation never means kill.
tmux-backed attempts may be detached and adopted after an app restart. A direct
attempt cannot survive the owning process and is reported as unrecoverable; a
new attempt may continue the stable Console.

The KF-ADR-019f86da-4f90-7153-a6c1-ab7a0a3cf481 main-process host becomes the product default after Mac parity and
streaming checks. Its process placement remains an implementation detail.

### 5. Inject a content-bound KFD-3 envelope

Every attempt binds `kungfu.agent-console-envelope/v1`: workspace, Console,
attempt, provider/runtime profile, active Profile roots, optional WorkRef, and
the local context/capability/Profile entrypoints. Provider adapters translate
the same envelope to Codex or Claude bootstrap semantics. The envelope points to
installed authority; it does not copy a static marketing prompt.

The product smoke asks the launched agent what it can do in Kungfu and requires
evidence that it queried the installed context/capability/Profile surfaces.

### 6. One public action path drives work and refresh

Starting/restoring a Console, creating work, changing State, submitting
evidence, and closeout are self-describing plans/actions/receipts. GUI controls
and agents invoke the same KFD-3/Profile registry. A successful admitted receipt
identifies affected Profile/entity/query keys and invalidates only the relevant
Dashboard query plans; bounded debounced refresh remains a loss-tolerant
fallback.

Cost comes from bound attempt usage Facts, State from admitted work Facts, and
Proof from receipts, evidence, queries, and assessments. Transcript and exit
code are observations, never automatic completion proof.

### 7. External report remains an equal product path

Users may run agents in another terminal, IDE, app, or host. Existing report and
receipt surfaces continue to feed the same Dashboard with visible source and
evidence strength. The built-in Console is the low-friction default, not a
capture mandate.

## Versioned contracts

The config contract version 2 owns:

- `kungfu.agent-runtime-profile/v1` in the machine-global config schema;
- `kungfu.work-ref/v1`;
- `kungfu.work-console-registry/v1`; and
- `kungfu.agent-console-envelope/v1`.

WorkRef/Profile roots and envelope roots are content-bound. Work bindings require
a WorkRef; workspace-assistant bindings require no WorkRef. Negative fixtures
must reject unbound work Consoles, drifting roots, opaque extra launch fields,
invalid presentation width, and missing discovery entrypoints.

## Consequences

- Positive: a Go card can become one stable, recoverable agent working surface;
  Dashboard and Console close the decision/execution loop without making the UI
  an authority.
- Positive: Week/Day, Task/Job, Case, and other qualified Profiles can reuse the
  same Console Runtime through WorkRef.
- Cost: a machine-global runtime-profile catalog, a workspace Console registry,
  provider bootstrap adapters, and receipt-driven query invalidation are new
  maintained surfaces.
- Compatibility: the existing managed-run and Atlas/report commands remain
  compatibility paths. They must converge on the public plans/receipts rather
  than being removed before parity exists.
- Non-goals: general IDE features, cloud chat sync, provider credential
  management, transcript-as-proof, cross-host live PTY migration, or a second
  Mission/Go store.

## Delivery gates

1. Contract schemas and negative fixtures.
2. Runtime-profile discovery/configuration with CLI/GUI parity.
3. Stable Console/attempt registry and tmux/direct lifecycle parity.
4. Versioned envelope and real Codex/Claude discovery smoke.
5. Go-card and assistant launch through public Profile actions with live query
   invalidation.
6. external-report and portable-bundle parity.
7. Mac packaged-product smoke and Shifu promotion. Linux CI is not a gate for
   this delivery cut.

The PR #2184 convergence slice centralizes the exact active-Work lease and
observer projection behind the shared Agent Session contract. Node, Python,
API, and TUI qualification now exercise the same WorkRef identity and preserve
the rule that provider exit cannot settle Work.
