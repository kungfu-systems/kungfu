# KF-ADR-019fb2de-4a59-7bf4-8231-b32b62aa7e9b: Project, Work, and Agent are the complete first-layer product model

- Status: accepted
- Date: 2026-07-30

## Context

Kungfu's authority model needs precise objects such as Initiative, Assignment,
Episode, Claim, Assessment, Decision, and Project Cut. Exposing all of them as
first-use navigation made a new user learn the implementation before they
could ask an Agent to do useful work. The product also projected overlapping
Workspace, Starter Project, Work Control, and Portfolio views, so the same
local repository appeared to be several different things.

The Alpha release needs one model that works in the TUI, GUI, and CLI without
weakening exact authority or retained evidence. A local Git repository is
already the object users understand. The product can bind it to `.kungfu`
without making that storage and authority layout a prerequisite concept.

## Decision

The complete first-layer object model is **Project, Work, Agent**.

1. A Project is one local directory and its retained Kungfu evidence.
   **Projects** is the persistent machine-local library of opened or
   initialized Project directories.
2. Work is one bounded outcome inside a Project. **All Work** is the active,
   completed, or complete machine-local projection across available Projects.
3. An Agent is the selected provider process that performs or independently
   reviews Work.

The first entry is not a replacement work interface. It teaches the user's
existing Agent the exact local Kungfu capability through `kungfu agent brief`.
GUI and TUI remain optional control and observation surfaces, with Agent Work
Lab and Project Tour available as progressive-disclosure learning routes.
README, CLI, GUI, TUI, Lab, and Tour must converge at that same point: first
make the bundled or standalone CLI discoverable, then give the existing Agent
the exact brief prompt, and complete shared onboarding only after durable Work
starts or binds. Completed or dismissed onboarding opens Core Work directly;
it does not require Lab inspection, KFX admission, or native renderer startup.
KFX execution and Work settlement retain their independent fail-closed gates.
After first use, low-frequency onboarding re-entry belongs in the GUI Help menu
and the TUI `/onboarding` command rather than permanent daily-work chrome.
Project Tour presents this model as two bounded episodes: the first establishes
Project, Work, and Agent through an ordinary delivery; the second resumes the
same retained Work to demonstrate failure recovery, independent review, and
settlement. Each episode is independently playable, while an `all` mode keeps
one continuous evidence story for CI and full demonstrations.
PR 2454 projects those episodes as separate 1x auditable-demo entries so each
episode keeps an independent completion sentinel, timing budget, and native
1080p/720p evidence chain without changing the continuous `all` route.

Every interactive surface presents the same golden path:

```text
Teach the existing Agent with kungfu agent brief -> New or Open Project -> Create or select Work -> Run Agent -> Review and complete Work
```

The CLI projects the same model through `kungfu project ...` and
`kungfu run <agent> [task]`. The no-argument `kungfu` entry remains the TUI;
there is no public `kungfu tui` compatibility alias.
Default `kungfu --help` exposes only `agent`, `project`, and `run` command
families under the Project, Work, Agent model. Existing expert commands remain
directly callable and are discoverable through `--help-all` and
`--help-section`, without occupying the first-use navigation layer.

Initiative, Assignment, Episode, Claim, Assessment, Decision, Project Cut,
Profile, and workspace/data-home terminology remain valid internal authority
or detail-layer concepts. They may appear in evidence, diagnostics, APIs, and
explicit explain views. They must not become first-layer navigation, calls to
action, or prerequisites.

The executable boundary is
`framework/product/project-work-agent.contract.json`, qualified by
`./shifu check:project-work-agent-product`. Internal authority contracts remain
the source of truth for admission, execution leases, review, and completion;
the product shell does not acquire that authority.

## Consequences

Users can start from an existing repository without learning Kungfu-specific
ontology. TUI, GUI, and CLI can evolve independently while their first-layer
objects and golden path remain mechanically checked. Projects become a
machine-wide locator, while `.kungfu` remains Project-local evidence.

The cost is a deliberate progressive-disclosure layer: diagnostics and explain
views must translate between Work and the exact internal Assignment and Episode
coordinates. New first-layer objects require a superseding ADR and contract
change, rather than appearing opportunistically in one surface.

This decision is falsified if a fresh user must choose an Initiative,
Assignment, Profile, Workspace, or Portfolio to start ordinary Work; if the
same Project cannot be found from Projects; if All Work omits retained
Project-local Work; or if a public surface launches an Agent without the exact
Work authority plan.
