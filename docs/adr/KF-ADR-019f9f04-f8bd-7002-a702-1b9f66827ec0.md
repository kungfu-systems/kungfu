# KF-ADR-019f9f04-f8bd-7002-a702-1b9f66827ec0: Maintainability governance uses read-only composite regression ratchets

- Status: accepted and implemented; terminal evidence remains exact-head bound
- Date: 2026-07-26

## Context

Kungfu has more than 440,000 source lines across more than 5,400 tracked
source files. A semantic change may cross generated projections, language
boundaries, release gates, and product surfaces even when the edited file is
small. File length alone therefore cannot identify the responsibility,
dependency, fan-out, churn, amplification, or ownership costs that make a
change hard to reason about.

The architecture health budget was already close to its admitted threshold,
and the protected checkout deliberately rejects writes. Discovery that
installs dependencies, creates caches, generates files, or mutates the
checkout cannot be the source-level entry point for either an agent or a
maintainer. A maintainability floor must remain useful before a build exists
and must not convert historical debt into a blanket exemption for new debt.

## Decision

Kungfu adopts a read-only composite regression ratchet as the source-level
maintainability floor.

### Zero-write discovery

Build-free discovery and source acceptance must not install dependencies,
create caches, contact the network, generate files, or otherwise mutate the
checkout. The read-only Shifu entry resolves only committed repository
authorities and delegates mutating or build-dependent work to explicit later
stages.

### Composite budgets

Maintainability budgets classify files by language and responsibility instead
of applying one global line limit. The first stage enforces:

1. a hard cap for newly introduced eligible files;
2. non-growth for pre-existing files already above their classified budget;
3. exact baselines for admitted historical debt; and
4. deterministic reports suitable for source gates and review evidence.

Length is never accepted as a complete fitness signal. Subsequent
decomposition decisions must combine responsibility, dependencies, fan-out,
change history, semantic amplification, and ownership.

### Independent, expiring exceptions

An exception must identify an exact path, owner, independent approver,
rationale, expiry, and removal condition. The author cannot approve their own
exception. Exceptions never mutate the permanent baseline and cannot match
future files by pattern.

### Authority boundary

The semantic amplification graph is a projection over existing repository
authorities. It may expose which surfaces and owners a change reaches, but it
does not become a second semantic authority or redefine those surfaces.

The abstraction-integrity extension keeps that boundary by naming one owner,
one existing authority, legal variation axes, adapters, qualification routes,
and bounded exceptions for each representative topology. Its build-free
findings and weighted-debt ratchet classify parallel authority, duplicated
policy, leaked platform decisions, orphan adapters, and stale exceptions
without flattening legitimate provider, lifecycle, product, or durability
semantics. Product assembly has one explicit lifecycle-order owner. Desktop
packaging now materializes executable framework and product projections from
one base plus a product-only overlay, and fails source acceptance if either
projection drifts. Native file and directory durability mechanics now pass
through one internal cross-platform adapter while strict, best-effort, and
provider-owned durability semantics remain separate at their domain call
sites. These remediations reduce the representative abstraction-integrity
ratchet from three findings and weighted debt 18 to zero without widening an
exception.

### Terminal qualification boundary

Pull request 1551 proves the read-only source-governance stage. Authority
convergence, responsibility-hotspot decomposition, Linux product
qualification, and Windows product qualification remain separately owned
follow-up Assignments. This decision does not claim physical durability,
public release, or qualification on an unobserved platform.

The terminal hardening candidate adds cryptographically bound independent
waiver and baseline-transition governance, rejects responsibility-preserving
split and classification-laundering variants, inventories every supported
read-only route, and runs the complete source gate from a physically locked
cold checkout. It also retires duplicated KFX forwarding decisions and
extracts cohesive complexity-governance and Buildchain KFD runtime seams.
The versioned
[`terminal-evidence-matrix.json`](../../framework/maintainability/terminal-evidence-matrix.json)
binds all seven required Assignments to the exact protected commit being
qualified. It names the source, preflight, product, artifact, native Assignment,
and fresh independent-review selectors that must all resolve before terminal
settlement. A green run from another commit, a private-chat summary, or a
partially settled child cannot satisfy that matrix.

## Consequences

- Maintainers and agents receive a useful architecture and complexity signal
  before dependency installation or native compilation.
- New complexity cannot hide inside the historical baseline, while admitted
  legacy hotspots can be reduced incrementally.
- Reviews gain an explicit map from semantic families to existing authorities
  and downstream surfaces.
- Policy, baseline, and graph manifests add maintenance cost. Exact stale-entry
  and expiry checks make that cost visible rather than silently weakening the
  gate.
- A passing source gate is not proof that a large file has coherent
  responsibilities, nor is it product qualification. The retained follow-up
  Assignments own those stronger claims.

## Falsifiers

This decision is violated if read-only discovery writes to the checkout,
contacts the network, or requires installed dependencies; if a new
over-budget file passes without an exact independent exception; if a
pre-existing over-budget file grows without a valid exception; if line count
is treated as the sole fitness signal; or if the amplification projection
becomes a competing semantic authority.
