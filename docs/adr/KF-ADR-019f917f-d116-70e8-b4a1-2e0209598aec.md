# KF-ADR-019f917f-d116-70e8-b4a1-2e0209598aec: Derive the Primitive Catalog from existing authorities

- Status: accepted; implementation staged for protected review
- Date: 2026-07-24
- Category: primitive lifecycle / contract projection / release admission
- Preserves: Fact, Episode, Cut, Action Geometry, Domain Profile, Agent Work,
  incubation-passport, KFD, invariant, and language-boundary authorities

## Context

Kungfu already defines primitives through several independent, purpose-specific
authorities. Vocabulary names them, incubation passports decide where a new
object may live, KFD-1 declares shipped contracts, KFD-3 declares participant
surfaces, invariants qualify claims, the Work lifecycle matrix declares
operations, and the language boundary declares SDK and native ownership. A
hand-maintained inventory would duplicate these decisions and eventually
disagree with them.

The product still needs one exact query answering which primitives exist, what
their current maturity is, which language proofs are present, and which
evidence is missing. Birth, build, runtime dogfood, promotion, and release must
observe the same answer.

## Decision

The incubation passport registry is the sole primitive intake. Each passport
may carry `primitiveDeclarations`; each declaration points to its actual
authority and evidence. The declaration does not replace that authority.

`scripts/generate-primitive-catalog.mjs` joins six exact facets and records the
raw SHA-256 Root of each:

1. vocabulary;
2. incubation passports;
3. KFD-1 contracts;
4. invariant registry;
5. Work lifecycle operation matrix; and
6. layered API/language boundary.

The resulting `kungfu.primitive-catalog/v1` is generated byte-for-byte into
the framework contract, shipped config artifact, and a native C++ header. It
is a cache with a reproducible `catalogRoot`, never a second authority.

Primitive classification is mechanically explicit. A machine-readable
primitive artifact carries a top-level `kungfu.primitive.*` or
`kungfu.primitive-*` schema and a matching `primitiveId`. Source acceptance
discovers these markers in every tracked or unignored JSON file, while the
conventional contract, vector, operation-slot, and SDK-slot roots remain
managed even when a marker is malformed or missing. Every discovered or
managed artifact must join to exactly one matching passport declaration.
`primitive:new` defaults to a dry-run and creates all four marked slots plus
the passport entry only with explicit `--write`.

Language paths establish `implemented`; a separate proof path is required for
`proved`. A primitive marked `admitted` or `stable` must have proved C++,
Python, Node, and Rust states plus contract, vector, invariant, and retained
dogfood receipt evidence. Release admission calls the same verifier and fails
closed. Scaffold files and empty vectors never count as proof.

The native action runtime exposes the generated projection as
`primitive_catalog`. Its Root is compiled from the same generated bytes and
tested against the source projection. KFD-1 ships the contract and KFD-3
declares the query surface.

## Consequences

- Fact, Episode, Cut, Action Geometry, Initiative, Assignment, Work, Domain
  Profile, and Receipt are visible in one deterministic inventory.
- Existing maturity debt remains explicit; the catalog does not upgrade a
  primitive merely because source files exist.
- Adding a primitive through an ad hoc contract file fails before merge.
- Moving a marked primitive artifact outside the scaffold roots does not evade
  the declaration join.
- Promotion requires evidence rather than a label change.
- Updating any facet changes the catalog Root and requires regeneration.

## Commands

```sh
./shifu check:primitive-catalog
./shifu primitive:new -- --id example --name Example --layer example
./shifu primitive:new -- --id example --name Example --layer example --write
./shifu check:source
```
