# KF-ADR-019f9659-5560-7d9d-a143-78766f19ec85: Separate Primitive definition, admission, and availability planes

- Status: accepted
- Date: 2026-07-25
- Category: Primitive semantics / evidence admission / runtime observation
- Extends: KF-ADR-019f917f-d116-70e8-b4a1-2e0209598aec

## Context

The v1 Primitive Catalog closed intake, artifact discovery, language proof, and
release drift, but one row still mixed three different questions:

1. what a Primitive means and how it relates to other Primitives;
2. which implementation and qualification evidence exists; and
3. whether one runtime can use it at one perspective.

A scalar maturity label could obscure missing evidence. Source presence could
also be mistaken for runtime availability. Neither interpretation is sound:
semantic identity changes slowly, evidence accumulates by independent axes,
and availability may regress when a Profile, capability, authority, storage
owner, workspace, platform, or runtime health changes.

## Decision

### Definition Plane

The incubation passport remains the sole intake. A declaration must carry
durable identity, an explicit classification family, lifecycle state,
semantic authority, invariant references, and the strict admission rationale.
The hierarchy distinguishes:

- semantic substrates;
- ontology bindings;
- coordinates;
- domain projections;
- responsibility-bearing roles; and
- ordinary capabilities.

Action Geometry is an ontology binding. Initiative and Assignment are
responsibility-bearing roles that bind to it. A Domain Profile is a domain
projection. Ordinary commands and convenience APIs remain ordinary
capabilities unless they independently pass the Primitive threshold.

The machine gate requires independent durable semantics, an explicit
cross-domain or runtime relevance claim or non-claim, participation in a
responsibility or persistent-fact boundary, plus deletion, substitution, and
compression rationales. A name, file, command, schema marker, or scaffold
alone cannot satisfy the threshold.

Definition lifecycle is active, superseded, or retired. A superseded
definition keeps its historical Root and names an exact successor; a retired
definition has no active runtime claim. Historical Catalog Cuts remain
interpretable. Reusing an id for unrelated semantics is forbidden.

Typed depends-on, composes, binds, projects, and implements edges carry a
source, target, layer boundary, authority path, and authority Root. The Catalog
may project these edges but may not originate them. Self edges, unknown
targets, unrooted edges, and edges that erase layer distinctions fail closed.

### Admission Plane

The v2 Catalog removes the hand-authored maturity field. Each Primitive has a
derived vector with at least:

- semantic stability;
- implementation completeness;
- language conformance;
- artifact shipment;
- qualification;
- operational evidence; and
- retained-use evidence.

Every state names its derivation policy and exact evidence references. Missing
evidence remains an explicit lower state. The summary is a policy conclusion,
not an input and not mutable by changing a label. Admission still requires
complete four-language proof plus contract, vector, invariant, and retained
dogfood evidence. Release admission invokes the same verifier.

### Availability Observation Plane

Availability is never stored in the Catalog. A report binds one Primitive and
Catalog Root to an explicit runtime identity, workspace, platform, active
Profile Roots, authority/capability/storage-owner boundary, Cut Root and time,
health, stable reason codes, and evidence Roots.

The states are available, degraded, unavailable, and unknown. Availability is
non-monotonic and perspective-bound. Missing observation, stale Catalog
binding, malformed coordinates, and mismatched Primitive identity return
unknown; absent authority, capability, or storage owner returns unavailable;
degraded health returns degraded. No implementation path or Catalog membership
implies availability.

### Projection and migration

kungfu.primitive-catalog/v2 replaces the pre-stable v1 projection and native
header. Existing Primitive ids and authority paths are preserved; the former
scalar is not copied. Source, shipped config, native runtime, installed CLI,
KFD-3, documentation, and release admission consume the same Root-bearing v2
bytes.

Production consumption is a closed set enforced by source acceptance. The
passport authoring entrypoint and Catalog generator are unique; the native
runtime reads the generated header and the installed CLI reads the shipped
contract. A new producer or consumer, a runtime reach-through to the passport,
or a write path in a governed reader fails closed. The scanner covers explicit
authority anchors and therefore complements, rather than replaces, human review
of deliberately opaque code.

The public read-only surfaces are:

    kungfu primitive list --json
    kungfu primitive show fact --json
    kungfu primitive explain fact --json
    kungfu primitive graph --from assignment --json
    kungfu primitive availability fact --json
    kungfu primitive availability fact --observation observation.json --json

The no-observation form intentionally returns unknown.

## Consequences

- Definition, qualification, and runtime truth can change independently
  without one plane impersonating another.
- Primitive review costs increase because semantic rationales and relation
  authorities are mandatory; ordinary PRs do not pay this cost.
- Catalog generation remains deterministic and read-only.
- A runtime observation is useful only for its bound perspective and Cut.
- Existing evidence remains incomplete where the repository cannot prove
  conformance, shipment, operation, or retained use.
- External adoption and improved long-running Agent effectiveness are not
  established by this decision. They require separately authorized,
  longitudinal evidence and are future work.
