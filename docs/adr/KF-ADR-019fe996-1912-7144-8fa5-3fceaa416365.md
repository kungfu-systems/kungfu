## Context

The Fact kernel already separates stable object identity, immutable versions,
typed relation roots, reproducible Cuts, append-only revocation, and
proof-carrying query. Its generic relation record deliberately does not define
whether one relation is compatibility, causality, provenance, supersession, or
delegation. Downstream systems have therefore repeated those meanings in
transport manifests, workflow state, mutable indexes, and current-head checks.

Those repetitions lose important temporal distinctions. A later revocation can
appear to invalidate a result that was correct at an earlier Cut. A directed
compatibility statement can be treated as symmetric. Two individually valid
edges can become an undeclared transitive assertion. A graph search can choose
one of several authority paths without exposing the ambiguity. Finally, a
receipt can name the current result without binding the exact path and Cut that
produced it.

The neutral Core needs one content-addressed language for these facts before a
release Profile, Buildchain projection, or provider adapter specializes them.
It must extend the existing KFR2 and Fact Cut authorities rather than create a
mutable graph database or a third schema substrate.

## Decision

### Closed temporal records use KFR2

Predicate declarations, relation assertions, supersessions, revocations,
authority proofs, provenance objects, explicit path queries, and their receipts
are closed records in `kungfu.fact-root.canonical/v2`. The machine registry owns
their field ids, and the independent C++ and Python encoders must agree on exact
bytes, roots, and rejection. JSON remains an edge representation.

Every record binds its interpretation inputs. Predicate declarations bind
direction, operations, path policy, cycle policy, and governing authority.
Relation assertions bind the predicate, ordered endpoints, first valid Cut,
scope, authority, and admission roots. A provenance object binds its subject,
materials, relations, Cut, authority, and admissions without assigning domain
meaning to those roots.

### Time is an immutable Cut, not a clock or head

Queries name one exact Fact Cut root. `validFromCutRoot`,
`effectiveCutRoot`, and `revokedAtCutRoot` are evaluated only through the
bounded Cut ancestry supplied with the query. Supersession and revocation append
new facts. They do not edit relation bytes, Cut bytes, or an earlier query's
result. A mutable ref may be resolved at an outer boundary, but it cannot enter
the temporal query as identity.

### Direction, scope, and composition are explicit

The verifier follows `sourceRoot` to `targetRoot`; it never reverses an edge.
The requested operation must appear both in the predicate declaration and in
the applicable authority proof. The verifier does not search a graph. A caller
supplies the complete ordered relation path and a maximum depth no greater than
32. Multiple edges are rejected unless the predicate explicitly permits
bounded composition; even then, the receipt proves only the supplied path and
does not create an inferred direct relation.

### Authority ambiguity fails closed

A relation asserted directly by the required governing authority needs no
delegation proof. Every other relation requires exactly one immutable,
operation-scoped authority proof valid at the requested Cut. No proof is
`authority-missing`; more than one is `ambiguous-authority`. The verifier does
not rank or silently choose competing proofs.

### Positive and negative results are receipts

Every semantically evaluated query produces an immutable KFR2 receipt. It binds
the query root, status, stable failure code, Cut root, ordered relation roots,
authority proof roots, and explicit omission roots. Orphan roots, unknown
predicates, ambiguous authority, cycles, unscoped operations, and implicit
transitive acceptance all reject deterministically.

The Python query surface is an independent semantic projection over immutable
Fact roots. It cannot write journal authority, mutate a Cut, discover an
alternate path, or promote a projection to authority.

## Consequences

- Release and Buildchain Profiles can project their own predicates and objects
  without adding release vocabulary to Core.
- Old-Cut replay remains stable after later supersession and revocation facts.
- Callers must retain exact Cut lineage and submit the path they want verified;
  convenient ambient-head and graph-search behavior is intentionally absent.
- KFR2 gains closed schema entries, increasing the compatibility obligation for
  both independent encoders.
- A rooted path receipt proves the bounded semantic decision only. It does not
  prove universal truth, external side effects, provider durability, or work
  completion.

## Falsification and qualification

The deterministic fixture and Python gate cover accepted old-Cut and successor
paths plus orphan roots, unknown predicates, ambiguous authority, forbidden
cycles, unscoped operations, direction reversal, implicit transitivity, and
revocation. The existing KFR2 corpus independently fixes one temporal predicate
record's exact bytes and root and checks the complete C++/Python schema registry
parity.

Production release qualification is not claimed. It remains governed by the
existing Fact durability and release-admission decisions.
