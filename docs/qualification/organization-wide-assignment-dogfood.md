# Organization-wide Assignment dogfood

The installed-product control plane is qualified for default-on use by **new**
Kungfu Systems Agent tasks. This decision does not migrate historical work and
does not authorize a stable or public release.

The campaign used a promoted macOS arm64 build at source commit
`7aae2c562a1cee9a1cab9e94c95971d23f4820b1`, one logical Home Workspace, and
independent project workspaces in KFD and Buildchain. Both repositories closed
real Assignment lifecycles; Buildchain additionally published and continued
from a verified Project Cut.

## Qualified boundary

- Installed capture, admission, claim, kickoff, stage, completion claim,
  independent review, decision, closeout, seal, and offline verification pass.
- Home owns only the parent coordination state. Each project retains its own
  Fact, Episode, Assignment, Cut, seal, and local binding receipt authority.
- The Cut-bound Home/Buildchain relationship names stable workspace and
  Assignment identities plus exact state, Cut, Episode, request, capture, and
  admission roots; filesystem paths remain locators only.
- A clean KFD task worktree was removed after closeout. Its Git common-dir seal
  and binding remained independently verifiable.
- Relocated seal and binding bytes verify, while state and relationship tamper
  fail closed with non-zero exits.

## Rollout decision

New Kungfu Systems Agent tasks default to installed Kungfu Assignment capture
and lifecycle orchestration. Existing active, ready, archived, and historical
tasks are not migrated. Source Shifu is allowed only as an explicit,
diagnosed development fallback when the installed surface is missing a needed
operation.

The machine-readable evidence and exact roots are retained in
[`report.json`](evidence/assignment-organization-rollout/7aae2c562a/report.json).

## Release non-claims

This campaign does not qualify Windows, Linux, GUI, TUI, multi-user operation,
public installers, stable release, or real-user migration. Installed Kungfu can
inspect but not yet publish Project Cuts; the Xinfa brief has one command-shape
drift; and local Xinfa baseline bodies still need exact Git excludes. These are
tracked residual risks, not silently upgraded claims.
